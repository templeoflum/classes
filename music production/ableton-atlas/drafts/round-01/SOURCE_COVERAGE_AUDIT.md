## Ranked changes before choosing the collection

1. **Make a phrase-centered entry possible.** Define its boundary and broaden C's name. The initial set should test a musical relationship beyond “operate a loop” or “edit a note”; S004 already provides topic-level support. Create an original example, not a rewritten source exercise or a universal counterpoint rule.
2. **Select F's exact contextual question.** Narrow F's scope and identify one recording, artist account or documented practice linked to the seed examples. Separate what can be heard from what a source establishes about its making or history. This is a small research task, not a genre survey.
3. **Agree canonical homes for the overlaps.** Resolve playback in A versus choices in D, instrument layers in B versus musical roles in C, and operational level in A versus prominence in E. Give each connection a reason; do not make duplicate entries to populate territories.
4. **Remove the accidental intervention hierarchy.** Revise curriculum encounter 9's “only then targeted processing.” The source synthesis and outline support alternatives, not a rule that musical edits must precede processing. Preserve the useful subtraction example without making subtraction a preferred aesthetic.
5. **Use the first collection to test distinct kinds of understanding.** The fifteen-entry pilot pool is concentrated in initial operations and expressive response. Broaden selection enough to include a musical relationship and a sourced contextual connection. Treat Build Plan §2's one-per-territory instruction as a test of the accepted boundaries, not a reason to force all six to survive or to publish an unverified placeholder. The half-hour lesson still uses only the useful subset; teacher notes supply continuity with zero student follow-up.

## Prioritized verification queue

These are precise checks to perform when the relevant entries are selected, not checks completed by this audit. Existing corrections in Source Review §6 remain in force.

| Priority / trigger | Check and acceptable evidence |
| --- | --- |
| **1 — setup, recording or expressive-response entry** | Establish the learner's Live version/edition, actual instrument and keyboard/pedal setup. Verify monitoring, record/replay, velocity response, note-off/pedal interaction, and attack/release behavior in that exact setup. Consult the relevant instrument manual plus [Ableton latency guidance](https://help.ableton.com/hc/en-us/articles/209072289-How-to-reduce-latency). Record conditions; do not generalize one preset's response or treat slow attack as system delay. |
| **2 — first F entry, before learner-ready factual prose** | Confirm work/performer identity and any date, making-process or influence claim through an artist, label, archive or other relevant primary record. Audition the cited passage before claiming an audible feature. Course recommendations are leads; a similar sound does not establish influence or a particular device. A source and passage must be chosen before this check can close. |
| **3 — `perform-views` or capture entry** | Check the selected release's Session/Arrangement playback relationship, the specific recovery control, and the effect of the demonstrated state on recording/export. Start with [Live concepts](https://www.ableton.com/en/live-manual/12/live-concepts/) and confirm in a minimal working example during later production. Do not introduce a second abstract playback explanation elsewhere. |
| **4 — keeping/portability entry** | Check save/find/reopen and the distinction between referenced media, devices and a listening export using [file management](https://www.ableton.com/en/live-manual/12/managing-files-and-sets/). If a Live Clip is offered, separately verify what it preserves and destination-dependent restoration. No need to teach that format for the first saved idea. |
| **5 — only if selected: advanced movement, dynamics, stereo or transformation** | State the exact behavior under discussion, then use the selected device's primary manual and an original comparison. Prioritize source-register traps: automation versus clip modulation, detector source versus Gate action, warp mode assumptions, and fixed headroom/frequency claims. Unselected specialist topics remain later work. |

No numerical listening target, universal mixing law, historical lineage, device availability claim, or new DSP explanation is certified here.
